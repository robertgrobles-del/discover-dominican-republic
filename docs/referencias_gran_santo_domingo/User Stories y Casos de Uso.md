## User Stories y Casos de Uso 

Portal Turístico del Gran Santo Domingo 

**Versión:** 1.0 

**Estado:** Borrador Inicial **Fecha:** Junio 2026 

## 1. Objetivo 

Definir las principales historias de usuario y casos de uso que describen cómo interactuarán los diferentes tipos de usuarios con el Portal Turístico del Gran Santo Domingo. Este documento servirá como base para la planificación del desarrollo y las pruebas funcionales. 

## 2. Roles del Sistema 

Visitante 

Usuario que navega el portal sin autenticarse. 

Usuario Registrado 

Usuario con acceso a funciones personalizadas como favoritos. 

Autor 

Crea contenido. 

Editor 

Revisa y publica contenido. 

Administrador 

Gestiona el funcionamiento completo del portal. 

## 3. Épicas 

EP-01 Descubrir el destino 

Permitir a los usuarios explorar el Gran Santo Domingo mediante categorías, mapas y búsquedas. 

## EP-02 Consultar información 

Acceder a información detallada de lugares, restaurantes, hoteles, eventos y rutas. 

EP-03 Consumir contenido editorial 

Leer artículos, guías y recomendaciones. 

EP-04 Gestionar contenido 

Permitir la administración del contenido mediante un CMS. 

EP-05 Administración del portal 

Gestionar usuarios, configuraciones y auditoría. 

## 4. Historias de Usuario 

## US-001 Explorar lugares 

**Como** visitante 

**Quiero** navegar por los lugares turísticos 

**Para** descubrir sitios de interés. 

## US-002 Buscar contenido 

**Como** visitante 

**Quiero** utilizar un buscador 

**Para** encontrar rápidamente un lugar, restaurante, hotel o evento. 

## US-003 Ver detalles 

**Como** visitante 

**Quiero** consultar la ficha completa de un lugar 

**Para** conocer su ubicación, horarios, historia y servicios. 

## US-004 Consultar eventos 

**Como** visitante 

**Quiero** visualizar los eventos próximos 

**Para** planificar mi visita. 

## US-005 Consultar rutas 

**Como** visitante 

**Quiero** explorar rutas sugeridas 

**Para** optimizar mi recorrido por la ciudad. 

## US-006 Leer guías 

**Como** visitante 

**Quiero** acceder a artículos y recomendaciones 

**Para** conocer mejor el destino. 

## US-007 Guardar favoritos 

**Como** usuario registrado 

**Quiero** guardar lugares y eventos favoritos 

**Para** consultarlos posteriormente. 

## US-008 Compartir contenido 

**Como** visitante 

**Quiero** compartir un lugar o evento 

**Para** recomendarlo a otras personas. 

## US-009 Administrar lugares 

**Como** editor 

**Quiero** crear y actualizar lugares turísticos 

**Para** mantener la información actualizada. 

## US-010 Administrar eventos 

**Como** editor 

**Quiero** publicar y modificar eventos 

**Para** mantener la agenda cultural vigente. 

## US-011 Gestionar categorías 

## **Como** administrador 

**Quiero** administrar categorías y etiquetas 

**Para** organizar el contenido del portal. 

## US-012 Gestionar usuarios 

**Como** administrador 

**Quiero** administrar usuarios y roles 

**Para** controlar los permisos del sistema. 

## 5. Casos de Uso 

## CU-01 Buscar un lugar 

## **Actor:** Visitante 

## **Flujo principal:** 

1. Accede al buscador. 

2. Introduce un término. 

3. El sistema muestra resultados. 

4. Selecciona un resultado. 

5. Visualiza la ficha del lugar. 

## CU-02 Consultar un evento 

## **Actor:** Visitante 

1. Accede a Eventos. 

2. Filtra por fecha o categoría. 

3. Selecciona un evento. 

4. Consulta la información completa. 

## CU-03 Crear un lugar 

## **Actor:** Editor 

1. Accede al CMS. 

2. Selecciona “Nuevo Lugar”. 

3. Completa la información. 

4. Guarda como borrador o publica. 

5. El sistema valida y registra el contenido. 

## CU-04 Publicar un artículo 

## **Actor:** Editor 

1. Crea el artículo. 

2. Asocia categorías e imagen. 

3. Envía a publicación. 

4. El sistema genera la URL y publica el contenido. 

## CU-05 Gestionar usuarios 

## **Actor:** Administrador 

1. Accede al módulo Usuarios. 

2. Crea, edita o desactiva usuarios. 

3. Asigna roles y permisos. 

4. Guarda los cambios. 

## 6. Priorización (MoSCoW) 

## Must Have 

- Navegación. 

- Buscador. 

- Lugares. 

- Restaurantes. 

- Hoteles. 

- Eventos. 

- Rutas. 

- Blog. 

- CMS. 

- Gestión de usuarios. 

## Should Have 

- Favoritos. 

- Compartir contenido. 

- Filtros avanzados. 

- Contenido relacionado. 

## Could Have 

- Comentarios. 

- Valoraciones. 

- Notificaciones. 

- Listas personalizadas. 

## Won’t Have (Versión Inicial) 

- Reservas. 

- Pagos. 

- Marketplace. 

- Chat en línea. 

## 7. Definición de Terminado (Definition of Done) 

Una funcionalidad se considerará completada cuando: 

- Cumpla los requisitos del PRD. 

- Respete las reglas de negocio. 

- Pase las pruebas funcionales. 

- Sea responsive. 

- Cumpla los estándares de accesibilidad. 

- Esté documentada. 

- Haya sido aprobada por el Product Owner. 

## Aprobación 

Este documento define la interacción esperada entre los usuarios y el Portal Turístico del Gran Santo Domingo, sirviendo como referencia para la planificación, desarrollo y validación funcional del sistema.
